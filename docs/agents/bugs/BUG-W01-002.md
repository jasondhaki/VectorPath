# BUG-W01-002 — Short local phone numbers (7–8 digits) are not minimized

- Severity: **Low** (partial privacy false negative; architecture §6.2 states redaction is imperfect).
- Unit / suspected owner: U18 · vp-domain · `lib/domain/redaction/redact.ts` (9-digit minimum in `isPhoneRun`).
- Found by: vp-qa probe, 2026-10-21.

## Repro

`redactContacts("Tel: 555-0123").text` returns `"Tel: 555-0123"`, unchanged. A labelled local number without an area code (US 7-digit, or a BD landline such as `Phone: 9123456`) is kept.

## Expected / actual

- Expected: a digit run that directly follows a phone label (`Tel`, `Phone`, `Mob`, `Mobile`, `Cell`, `WhatsApp`, `Fax`) is removed, even when it is shorter than 9 digits.
- Actual: it is kept, because of the 9-digit minimum. That minimum is correct for unlabelled runs, since it protects years and versions.

## Suggested direction

Apply a label-anchored rule with a lower minimum (for example 6 digits) only when the run immediately follows a phone label. Keep the unlabelled 9-digit rule.

## Status: CLOSED — vp-qa re-verification 2026-10-21

The fix is `PHONE_LABEL` in `redact.ts`, which lowers the minimum to 7 digits directly after a phone label.

- **Original repro `Tel: 555-0123`:** now removed.
- **QA adversarial cases, all removed:** `Phone - 9123456`, `Mobile no. 5550199`, `Ph: 555 0123`, `Cell #5550123`, `Fax: 020 7946 0958`.
- **Kept, no over-redaction:** `Mobile app developer, 2019 – 2021`, `Cell culture lab, 2018 - 2020`, `Phone support for 120 customers daily`, `Telephone sales, 5 years`.
