# BUG-W01-003 — Orphaned interactive `prisma migrate dev` process left running against the dev DB

- Severity: **Low** (environment hygiene; coordination hazard in ai-workflow-rules §10 for "one schema writer").
- Suspected owner: vp-backend (U03 session) / lead to stop it.
- Found by: vp-qa process inspection, 2026-10-21.

## Evidence

`Get-CimInstance Win32_Process` shows node PID **20940** with command line `node D:\VectorPath\node_modules\prisma\build\index.js migrate dev`. It is still running. The U03 handoff records that `prisma migrate dev` waited for input because of the HNSW drift, and that the builder stopped it. The process is still alive.

## Expected / actual

- Expected: no schema-writing process remains after U03, so the schema lock can be released cleanly.
- Actual: an interactive migrate process is still waiting on stdin. It may hold a connection or advisory lock on the dev DB (127.0.0.1:55432).

QA did not stop it, because the process is not QA-owned.

## Action

Lead or backend confirms the process is stale, stops it, then releases the schema lock. Follow-up: the README `db:migrate` procedure note (U03 review R2-2).

## Status: CLOSED — vp-qa verification 2026-10-21

Lead reported stopping PID 20940. QA checked independently:
- `Get-CimInstance Win32_Process` shows no node process whose command line contains `prisma` and `migrate`.
- `Get-Process -Id 20940` finds no process.

Schema-lock release is the lead's call; QA did not check it.
