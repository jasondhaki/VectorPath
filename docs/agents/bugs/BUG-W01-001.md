# BUG-W01-001 — Common GB/US/IN address lines survive contact minimization

- Severity: **Medium** (privacy false negative, I07 minimization). Not a breach of the written U18 "Done when" line, which is about phones/quotes. **Must be fixed before U19b integrates redaction with real uploads.**
- Unit / suspected owner: U18 · vp-domain · `lib/domain/redaction/redact.ts` (`ADDRESS_PART`, `STREET_LINE`, `isAddressLine`).
- Found by: vp-qa independent probe, 2026-10-21, candidate = uncommitted working tree.

## Repro

Use fictional strings only. `redactContacts(s).text` returns each input **unchanged**:

| Input | Why it is missed |
|---|---|
| `Flat 3B, 22 Baker Street, London` | only one `ADDRESS_PART` hit and no comma directly after the street suffix |
| `1600 Pennsylvania Avenue NW, Washington, DC 20500` | `STREET_LINE` needs the comma straight after the suffix, but `NW` sits in between |
| `Apt 4, 55 MG Road, Bengaluru 560001` | `MG` is not `[A-Z][a-z]+`; `Road` has no number after it |
| `Flat 3B, Rose Court` | single part |
| `London NW1 6XE` (postcode line) | no postcode rule |
| multi-line CV header `Jane Example\n22 Baker Street\nLondon NW1 6XE\nUnited Kingdom` | the street line has no comma tail, so every line is kept |

These are removed correctly, for contrast: `22 Baker Street, London NW1 6XE`, `221B Baker Street, London NW1 6XE`, `12 Elm St, Springfield, IL 62701`, `Address: 22 Baker Street, London`, `House 12, Road 5, Dhanmondi, Dhaka 1205`.

Probe: a scratch `tsx` script that calls `redactContacts`. Nothing was added to the repository.

## Expected / actual

- Expected (architecture §6.2, I07): address lines in supported countries (BD/IN/GB/US) are minimized. The multi-line CV header block is the most common form.
- Actual: the GB/US/IN header and street forms above are persisted verbatim.

## Suggested direction (owner decides)

1. A street line with no comma tail when the next line looks like a postcode or city.
2. GB postcode (`[A-Z]{1,2}\d[A-Z\d]? \d[A-Z]{2}`), US `, [A-Z]{2} \d{5}` and IN 6-digit PIN after a city.
3. Allow uppercase abbreviations or directionals (`MG`, `NW`) between the number and the suffix.
4. Flat/Apt + number followed by a street line.

Add negative tests that keep experience lines such as "Drive sales growth by 20%" and "Team lead for 12 engineers since 2019", which are already kept today.

**Known limitations, carried to U19b (review screen) and U26 (methodology copy):**
1. **Over-redaction:**
   - What: a line ending in a gazetteer city followed by a 6-digit number is removed even when it is not an address.
   - Examples: `Sales target, Mumbai 400001`, `Branch code: Mumbai, 400001`, `Plant: Pune 411001`.
   - Assessment: rare; it errs toward privacy.
2. **Leak:** `PO Box 1234, Nairobi`.
   - Assessment: outside the BD/IN/GB/US scope; rare.
3. **Not an address by itself:** a city/country-only location such as `Jane Example, Mumbai, India` or `Lives in Dhanmondi, Dhaka` is kept.
   - Assessment: accepted. It identifies an area, not an address.
4. **Moved to [BUG-W01-004](BUG-W01-004.md), not counted as limitations:**
   - `Village Rampur, Dist. Sitapur, UP 261001`: the dotted `Dist.` form and an abbreviated state.
