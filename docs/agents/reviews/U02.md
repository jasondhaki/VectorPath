## Specific checks requested by lead

1. **Tokens.** These match exactly, with one token set and no raw colours in components (`check-tokens.mjs` ROOTS app/components, only globals.css allowed). The contrast test computes from the real CSS. Of the three failing pairs, line-2 (`border-line-strong`), danger-on-selection and line-1 are not currently used in a failing combination: `text-destructive` appears only on an icon over `bg-card` (`error-state.tsx:7`), and `line-strong`/`selection` are unused. Their restriction lives only in test comments, not in ui-context (see #5).
2. **Accessibility.**
   - The skip link targets `<main id="main" tabIndex={-1}>` (`app-shell.tsx:33-38,76`). There is a single `main`. The `h1` is unique on `/` because the brand is a link, not a heading.
   - Disabled nav items carry sr-only "(not available yet)" (`:174`).
   - Reduced motion is handled at `globals.css:110-119`, which also stops `animate-spin`.
   - The popover can be keyboard-opened and closed natively, but see #2 and #3.
   - Route-level states have no `h1` (#4).
3. **Honesty.**
   - Every nav item has `built: false` (`nav-items.ts:25-32`), so `resolveHref` returns null and nothing renders as a link.
   - The flags read `FEATURES` from `lib/config/features.ts:2-13`. `paths`, `jobCompare` and `marketPulse` are all false, so those items are hidden (`nav-items.ts:41-43`).
   - The topbar says "No active profile" rather than inventing one.
   - The dev gallery calls `notFound()` when `process.env.NODE_ENV === "production"` (`app/dev/components/page.tsx:9`). Next inlines NODE_ENV at build time, so a production build renders the 404 for this route, both at prerender and at request time. It cannot render in prod. E2E runs `next build && next start` (`playwright.config.ts:15`), so E2E cannot see the gallery. QA item 6 needs the coordinated dev server.
4. **error.tsx.**
   - It does not render `error.message` or `digest`; it only destructures `reset` (`app/error.tsx:8`).
   - Client JS is limited to error.tsx, which Next requires. The shell is a server component and uses the native popover.
   - No remote fonts.
   - The copy makes an unverifiable claim (#1).
5. **Tests.** They are meaningful, not snapshots:
   - computed contrast thresholds plus a spec/CSS drift check;
   - synthetic lint violations;
   - `resolveHref` substitution, encoding and null cases;
   - flag hiding and nav order;
   - markup assertions for skip link, `aria-disabled`, the no-profile state and the profile render.
6. **Ownership.** All changed paths are frontend-owned.
